# B2.5 language and local-model assessment

**Decision: ship the deterministic offline interpreter. No semantic model is selected or integrated.** A1 flexible command play and A1a grounded story are implemented through supported action families, references, corrections, compound requests, contextual options and authored consequences. This does not establish arbitrary-English understanding.

## Actual evaluation

The retained `language-results.json` in the final B2.5 validation run contains 47 representative requests with expected classifications, typed proposals and individual timings. They cover polite paraphrases, word-number movement, references, questions, compounds, corrections, character commands, ambiguity, negation, unknown targets, excessive steps and unsupported tasks. Compound checks verify both actions, not just the first verb. Forty-seven expected outcomes passed, including deliberate refusals; that is a bounded regression corpus, not an independent natural-language accuracy benchmark.

In the measured September 23 local run (`run-20260924T030110Z`), interpretation took 2–92 microseconds, median 37 microseconds. Static engine memory increased 100,516 bytes across parsing and retaining all results. This is an allocation delta, not total process RSS, peak memory or an isolated parser measurement. Game and render latency are separate. Actual-scene tests then executed the command-driven opening, powers, rewards, party branches, both retrieval methods, Stop/corrections and restart. A later final run, if listed in the delivery record, supplies its own raw measurements.

Offline behavior is structural: the interpreter imports no network/provider client, loads no weights and needs no credentials. Unknown language returns clarification/guidance while exact actions and displayed choices remain available. There is no running semantic backend to fail; no timeout, malformed-model-output or provider-failure test is claimed. The unsupported-request and deterministic-control tests cover the shipped no-backend behavior.

## Primary-document comparison — not a model benchmark

Checked the official [Qwen3-0.6B model card](https://huggingface.co/Qwen/Qwen3-0.6B), [llama.cpp repository](https://github.com/ggml-org/llama.cpp) and [grammar documentation](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md) during this implementation. Qwen documents a 0.6B-parameter model, optional non-thinking operation and local runtime support. llama.cpp documents Apple Silicon support and grammar-constrained output. These capabilities suggest a plausible bounded intent-proposal experiment; grammatical output alone does not establish correct intent, target identity or safe execution.

| Criterion | Shipped interpreter — run | Qwen3-0.6B with llama.cpp — documentation only |
| --- | --- | --- |
| Interpretation | 47 expected corpus outcomes; ordinary journeys executed | Potential wider phrasing; local intent accuracy untested |
| Ambiguity | Names/choices; unknown or negated requests refused | Must be constrained to clarification or supported typed proposals; untested |
| Response time | Per-request measurements above | Not measured; no inference run |
| Memory | Static allocation delta above; no model weights | Runtime/weights/context footprint not measured |
| Offline | Operates entirely within Godot | Local inference is plausible after installation; untested here |
| Integration | GDScript and existing scene authorities | Would add model distribution, process lifecycle, schema validation and timeouts |
| Failure | Unknown requests leave choices and exact controls usable | Would require fallback on timeout/unavailable/invalid output; not implemented or tested |

No cloud provider was assessed in execution; no model was downloaded or run. Therefore this work does **not** demonstrate that the small model improves understanding on this Mac, and does not claim it is slower or less accurate. The current bounded game can ship without that dependency. If owner play reveals recurring useful phrasings the grammar cannot handle, retain those examples and compare a separately identified local candidate against the same action/context contract. Model proposals must never mutate inventory, reveal unknown facts, provide character feed access or declare unobserved success.

Known language limits include unsupported unrestricted goals (for example, “get me somewhere less depressing”), unsupported verbs such as “stroll,” conditional plans, and fresh-room targets inside an already-bound cross-room plan. The refusal is visible and the current contextual choices remain playable. These limitations are explicit, not passed off as semantic-model capability.
